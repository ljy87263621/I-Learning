# 树与二叉树

## 1. 树的基本术语

树是一种一对多的非线性结构，通常从根节点向下表示层次关系。

| 术语 | 含义 |
| --- | --- |
| 根 | 没有父节点的节点 |
| 父节点 | 某节点的直接前驱 |
| 子节点 | 某节点的直接后继 |
| 度 | 一个节点拥有的子节点数 |
| 叶子 | 度为 0 的节点 |
| 层次 | 根为第 1 层，向下逐层加 1 |
| 高度/深度 | 树中最大层次 |

有序树关心孩子之间的左右顺序；二叉树是有序树，并且每个节点最多有两个孩子，分别称为左孩子和右孩子。

## 2. 二叉树性质

若根节点所在层为第 1 层：

- 第 `i` 层最多有 `2^(i-1)` 个节点。
- 高度为 `k` 的二叉树最多有 `2^k - 1` 个节点。
- 设叶子节点数为 `n0`、度为 2 的节点数为 `n2`，则 `n0 = n2 + 1`。

我需要区分的几种形态：

- **满二叉树**：每个节点要么没有孩子，要么有两个孩子。
- **完美二叉树**：所有非叶子节点都有两个孩子，且所有叶子在同一层，节点数为 `2^k - 1`。
- **完全二叉树**：除最后一层外均满，最后一层节点从左到右连续排列。
- **平衡二叉树**：这里按每个节点左右子树高度差不超过 1 来理解；遇到具体题目时，我会先确认题目采用的定义。
- **退化二叉树**：每个节点最多只有一个孩子，形态接近链表。

我把“满二叉树”和“完美二叉树”区分为：满二叉树要求每个节点的度为 0 或 2；完美二叉树还要求所有叶子位于同一层。判断具体问题时，我以题目明确给出的定义为准。

## 3. 存储方式

### 3.1 链式存储

```c
typedef struct TreeNode {
    int data;
    struct TreeNode *left;
    struct TreeNode *right;
} TreeNode;
```

链式存储适合形态不规则的二叉树，空孩子用 `NULL` 表示。

### 3.2 顺序存储

按层从 1 开始编号时：

- 节点 `i` 的父节点为 `i / 2`。
- 左孩子为 `2 * i`。
- 右孩子为 `2 * i + 1`。

顺序存储对完全二叉树非常合适；对稀疏树会浪费大量数组空间。

## 4. 四种遍历

设当前节点为 `root`：

- **前序**：根、左、右。
- **中序**：左、根、右。
- **后序**：左、右、根。
- **按层**：从上到下、从左到右，通常借助队列。

递归遍历模板：

```c
void preorder(TreeNode *root)
{
    if (root == NULL)
        return;
    visit(root);
    preorder(root->left);
    preorder(root->right);
}

void inorder(TreeNode *root)
{
    if (root == NULL)
        return;
    inorder(root->left);
    visit(root);
    inorder(root->right);
}

void postorder(TreeNode *root)
{
    if (root == NULL)
        return;
    postorder(root->left);
    postorder(root->right);
    visit(root);
}
```

每种遍历都访问每个节点一次，时间复杂度为 `O(n)`；递归栈空间为 `O(h)`，其中 `h` 是树高。

按层遍历的思路：根节点入队；队列非空时，取出队头并访问，再把非空左、右孩子入队。时间复杂度 `O(n)`，队列空间最坏为 `O(n)`。

## 5. 二叉搜索树 BST

BST 的核心不变量是：

```text
左子树所有键值 < 根节点键值 < 右子树所有键值
```

重复值的处理需要提前约定：可以禁止重复、在节点中计数，或统一放到左侧/右侧。下面的 BST 插入规则按“不插入重复值”处理。

### 5.1 查找和插入

从根节点开始比较：小于当前节点向左，大于当前节点向右，直到找到目标或遇到 `NULL`。

```c
TreeNode *bst_insert(TreeNode *root, TreeNode *node)
{
    if (root == NULL)
        return node;

    if (node->data < root->data)
        root->left = bst_insert(root->left, node);
    else if (node->data > root->data)
        root->right = bst_insert(root->right, node);
    else
        free(node);       // 这里选择忽略重复值

    return root;
}
```

### 5.2 删除

删除节点分三类：

1. **叶子节点**：直接删除。
2. **只有一个孩子**：让父节点直接连接它的孩子。
3. **有两个孩子**：用左子树最大节点（前驱）或右子树最小节点（后继）替换，再删除那个替代节点。

BST 的中序遍历结果是升序序列，这是检验 BST 是否正确的快捷方法。

### 5.3 性能

- 平衡或接近平衡：查找、插入、删除约为 `O(log n)`。
- 按升序或降序依次插入时可能退化成链表：最坏为 `O(n)`。
- BST 本身不保证平衡；如果我需要避免退化，就会考虑 AVL 或红黑树。

## 6. AVL 树

AVL 是严格平衡的 BST。对每个节点定义平衡因子：

```text
BF = height(left) - height(right)
```

要求 `BF` 只能为 `-1、0、1`。节点通常额外保存高度。

| 失衡类型 | 形态 | 修复 |
| --- | --- | --- |
| LL | 新节点插入左子树的左侧 | 右旋 |
| RR | 新节点插入右子树的右侧 | 左旋 |
| LR | 新节点插入左子树的右侧 | 先左旋左孩子，再右旋 |
| RL | 新节点插入右子树的左侧 | 先右旋右孩子，再左旋 |

插入或删除的基本流程：

1. 先按 BST 规则递归处理。
2. 回溯时更新每个节点的高度。
3. 检查平衡因子并执行对应旋转。
4. 返回旋转后的子树根。

AVL 查找、插入、删除均为 `O(log n)`，但维护平衡所需的旋转比红黑树更积极。

## 7. 红黑树

红黑树也是自平衡 BST，但不追求 AVL 那样严格的高度平衡，以减少调整次数。常见定义包含以下规则：

1. 每个节点为红色或黑色。
2. 根节点为黑色。
3. `NULL` 叶子视为黑色。
4. 红色节点不能有红色孩子。
5. 从任意节点到其后代 `NULL` 叶子的每条路径，黑色节点数量相同。

插入通常先按 BST 插入，并将新节点设为红色，再根据父节点、叔节点和祖父节点的颜色进行颜色翻转与旋转。删除时先把“有两个孩子”的情况转化为删除至多一个孩子的节点，再处理黑色高度变化。

### AVL 与红黑树的取舍

| 项目 | AVL | 红黑树 |
| --- | --- | --- |
| 平衡严格程度 | 更严格 | 较宽松 |
| 查找路径 | 通常更短 | 仍为对数级 |
| 插入/删除调整 | 可能更频繁 | 通常较少 |
| 实现难度 | 中等 | 较高 |
| 适合 | 查找明显多于修改 | 插入、删除频繁的通用有序容器 |
