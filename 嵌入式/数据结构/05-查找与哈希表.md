# 查找与哈希表

## 1. 查找方式概览

我把查找理解为在数据集合中定位满足条件的记录，主要方法有：

| 方法 | 前提 | 平均复杂度 | 最坏复杂度 |
| --- | --- | ---: | ---: |
| 顺序查找 | 无特殊要求 | `O(n)` | `O(n)` |
| 二分查找 | 数据已按键值有序 | `O(log n)` | `O(log n)` |
| BST 查找 | 维护搜索树关系 | `O(log n)` | `O(n)` |
| AVL/红黑树 | 维护平衡 | `O(log n)` | `O(log n)` |
| 哈希查找 | 设计哈希函数和冲突处理 | 平均 `O(1)` | 与冲突程度有关 |

二分查找适合静态或修改较少的有序数组；频繁插入删除时，维护数组有序的成本可能抵消查找收益。

## 2. 二分查找

在闭区间 `[left, right]` 中查找：

```c
int binary_search(const int a[], int n, int target)
{
    int left = 0;
    int right = n - 1;

    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (a[mid] == target)
            return mid;
        if (a[mid] < target)
            left = mid + 1;
        else
            right = mid - 1;
    }
    return -1;
}
```

二分查找的边界我这样检查：

- 我需要保证数组已经按查找方向有序。
- 我使用 `left + (right - left) / 2` 计算 `mid`，避免 `left + right` 溢出。
- `left <= right`、`mid + 1`、`mid - 1` 要和区间定义保持一致。
- 查找第一个或最后一个重复值时，我会在找到目标后继续收缩区间。

## 3. 哈希表

哈希表也称散列表、HashTable、映射表或字典。它通过哈希函数把键映射到数组下标：

```text
index = hash(key) % capacity
```

哈希表的核心不是“完全不比较”，而是先通过映射快速定位桶；发生冲突后，桶内仍然需要通过比较键值找到目标。

### 3.1 管理结构

```c
typedef struct HashNode {
    int key;
    int value;
    struct HashNode *next;
} HashNode;

typedef struct {
    HashNode **buckets;
    size_t capacity;
    size_t size;
} HashTable;
```

`buckets[i]` 表示第 `i` 个桶的冲突链表。我实现哈希表时还需要明确：键是否允许重复、删除如何标记、扩容阈值和内存释放策略。

## 4. 冲突处理

### 4.1 链地址法

每个桶保存一个链表，映射到同一地址的元素挂在同一条链上：

- 优点：实现直观，表装载超过数组长度后仍可工作。
- 缺点：冲突多时链表变长，查找退化；节点有额外指针开销。

### 4.2 开放地址法

所有元素都放在数组中，冲突后按探测序列寻找下一个空位：

- 线性探测：`h, h+1, h+2, ...`。
- 二次探测：按平方增量探测。
- 双重哈希：使用第二个哈希函数决定步长。

开放地址法删除时不能简单写成“空”，通常要使用墓碑标记，否则可能截断后续探测链。

## 5. 示例：除留余数法

表容量为 20，数据为：

```text
23, 34, 14, 38, 46, 16, 68, 15, 07, 31, 26
```

使用 `key % 20`：

| key | 地址 |
| ---: | ---: |
| 23 | 3 |
| 34 | 14 |
| 14 | 14 |
| 38 | 18 |
| 46 | 6 |
| 16 | 16 |
| 68 | 8 |
| 15 | 15 |
| 7 | 7 |
| 31 | 11 |
| 26 | 6 |

冲突发生在 `34/14` 和 `46/26`。使用链地址法时，它们分别进入桶 14 和桶 6 的冲突链表。

哈希表容量为 `capacity` 时，哈希地址通常计算为 `data % capacity`，这样可以使用全部桶位；处理负数键时，还必须将结果规范化为非负下标。

## 6. 哈希表的性能

设装载因子为：

```text
alpha = size / capacity
```

在哈希函数分布均匀、装载因子可控时，查找、插入和删除平均接近 `O(1)`。当冲突集中或装载因子过高时，性能会明显下降，极端情况下可退化为 `O(n)`。

实现时我会关注这些维护策略：

- 选择分布较好的哈希函数。
- 控制装载因子，达到阈值后扩容并重新哈希。
- 对字符串按字符累积计算哈希值，而不是只使用首字符或长度。
- 及时释放冲突链表中的节点。

## 7. 字符串哈希要点

- 字符串哈希函数通常按字符累积计算，不能只依赖长度或首字符。
- 映射到桶之后，仍需要在冲突链表或探测序列中用 `strcmp` 判断键是否真正相等。
- 装载因子越高，平均比较次数通常越多；扩容和重新哈希可以降低冲突链长度。
- 字符串作为键时，哈希表节点通常需要保存字符串副本或明确字符串所有权。

哈希表的映射负责缩小搜索范围；冲突链表中的字符串比较仍然是必要的相等性确认。

## 8. 选择查找结构

- 数据静态、连续存储、需要极快查找：排序数组 + 二分查找。
- 数据需要保持有序并频繁增删：AVL 或红黑树。
- 只关心按键快速定位、不要求有序遍历：哈希表。
- 数据量小或只扫描一次：顺序查找往往最简单。
