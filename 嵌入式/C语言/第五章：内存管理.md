## 1. 进程中的典型存储区域

具体布局由操作系统、链接器与 ABI 决定；以下是常见模型，不是 C 标准保证的地址布局。

| 区域 | 常见内容 | 生命周期 |
| --- | --- | --- |
| 代码段（`.text`） | 可执行指令 | 进程运行期间 |
| 只读数据（`.rodata`） | 字符串字面量、只读常量 | 进程运行期间 |
| 已初始化数据（`.data`） | 有初值的静态存储期对象 | 进程运行期间 |
| 零初始化数据（`.bss`） | 无显式初值的静态存储期对象 | 进程运行期间 |
| 栈 | 调用帧、自动对象 | 进入代码块到离开代码块 |
| 堆 | 动态分配对象 | `malloc` 成功到 `free` |

嵌入式裸机程序可能没有进程/虚拟内存概念，但 `.text/.data/.bss`、栈和堆的资源约束仍然关键。

## 2. 动态分配 API

```c
#include <stdlib.h>

int *items = malloc(count * sizeof *items);
if (items == NULL && count != 0) {
    /* 分配失败 */
}

/* 使用 items */
free(items);
items = NULL;
```

| 函数 | 行为 |
| --- | --- |
| `malloc(size)` | 分配 `size` 字节，内容未初始化；失败返回 `NULL`。 |
| `calloc(count, size)` | 分配 `count * size` 字节并置零；需防乘法溢出。 |
| `realloc(ptr, size)` | 调整原分配块；失败时原 `ptr` 仍有效，故不要直接覆盖原指针。 |
| `free(ptr)` | 释放由分配函数返回的整块内存；`free(NULL)` 安全。 |

`malloc` 的返回值在 C 中无需强制转换；强转可能掩盖缺少 `<stdlib.h>` 的问题。

## 3. 所有权规则

1. 每次成功分配都应有一个明确的释放责任人。
2. 每块分配内存最多释放一次，且只能传给 `free` 原始分配指针或 `NULL`。
3. `free` 后指针值未自动改变，继续解引用或再次释放都是错误；常将本地所有者置为 `NULL`。
4. 释放内存不保证清零，也不保证其地址不再被后续分配复用。

### `realloc` 正确写法

```c
int *grown = realloc(items, new_count * sizeof *items);
if (grown == NULL && new_count != 0) {
    /* items 仍可用，处理失败 */
} else {
    items = grown;
}
```

## 4. 常见错误清单

| 错误 | 后果 | 预防 |
| --- | --- | --- |
| 内存泄漏 | 对象不可再访问但未释放 | 统一清理出口；资源申请后立即规划释放。 |
| 越界读写 | 未定义行为、数据破坏 | 保存容量和长度；所有索引做范围证明。 |
| 使用已释放内存 | 悬垂指针 | `free` 后不再使用；缩短别名存活范围。 |
| 重复释放 | 未定义行为 | 明确唯一所有者；释放后置空。 |
| 整数溢出导致少分配 | 后续写越界 | 分配前检查 `count > SIZE_MAX / sizeof *ptr`。 |

`bzero` 不是 ISO C 标准函数；需要清零已存在的内存时使用 `<string.h>` 的 `memset(ptr, 0, size)`，但不要用它清零含有资源语义的 C++ 对象（本库讨论的是 C）。
