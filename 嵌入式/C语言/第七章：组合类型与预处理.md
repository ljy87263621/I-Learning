# 组合类型与预处理

[[欢迎|返回索引]]

## 1. 结构体

结构体将不同类型成员组合成一个对象；成员依声明顺序存在于对象中，编译器可插入填充字节。

```c
struct sensor {
    int id;
    float value;
    unsigned enabled;
};

struct sensor s = {.id = 1, .value = 23.5f, .enabled = 1};
struct sensor *p = &s;

s.value = 24.0f;  // 实体用 .
p->value = 25.0f; // 指针用 ->，等价于 (*p).value
```

- 指定成员初始化允许改变书写顺序、省略成员，并对新增成员更稳健。
- 结构体可整体赋值，语义为逐成员拷贝；若成员含指针，只会复制地址，可能产生共享所有权问题。
- `sizeof(struct T)` 通常不等于成员大小之和，原因是对齐和尾部填充。

## 2. 对齐与布局

对象的**对齐要求**决定其地址必须满足的边界。编译器会在成员间插入填充，使成员满足各自对齐要求；结构体自身通常按成员最大对齐要求对齐，末尾也可能补齐。

```c
struct example {
    char tag;
    int value;
};
```

上例常见大小为 8，而非 5。跨平台二进制协议不要直接依赖原生结构体布局；应逐字段编解码或明确使用协议定义的字节序。

- `_Alignof(type)` 可查询对齐要求（C11）。
- GNU 的 `__attribute__((packed))`、`__attribute__((aligned(N)))` 是非标准扩展。压缩布局可能造成未对齐访问和性能/硬件异常，应仅用于受控的硬件或协议边界。

## 3. 位域

```c
struct flags {
    unsigned ready : 1;
    unsigned mode  : 3;
};
```

- 位域宽度以位计，声明类型必须是实现允许的整数类型。
- 位域不能取地址；布局顺序、跨存储单元方式和整体大小具有实现定义特性。
- 位域适合本机受控环境的标志位；不应用于可移植的网络/文件二进制格式。

## 4. 联合体

联合体成员共享同一段存储，大小至少能容纳最大成员：

```c
union value {
    int integer;
    float decimal;
};
```

一次写入一个成员后，读取另一成员来解释相同位模式的行为受语言规则与实现影响；可移植程序应只读取最后写入的成员，或用 `memcpy` 进行位级转换。联合体常与标签字段配合表达“多选一”数据。

## 5. 枚举

```c
enum state {
    STATE_IDLE,
    STATE_RUNNING,
    STATE_ERROR
};
```

枚举为一组整型常量命名，提升可读性；其底层表示由实现决定。对外存储或通信时使用固定宽度整数，并显式定义取值。

## 6. 预处理

预处理发生在编译前，主要处理包含、宏和条件编译。

```c++
#ifndef SENSOR_H
#define SENSOR_H

#define ARRAY_LEN(a) (sizeof(a) / sizeof((a)[0]))

#if defined(DEBUG)
#define LOG(...) printf(__VA_ARGS__)
#else
#define LOG(...) ((void)0)
#endif

#endif
```

| 指令 | 用途 | 注意 |
| --- | --- | --- |
| `#include` | 文本包含头文件 | 头文件使用 include guard 或 `#pragma once`（非标准）。 |
| `#define` | 定义宏 | 宏是文本替换，不做类型检查；参数和整体结果都加括号。 |
| `#if/#ifdef/#ifndef` | 条件编译 | 用于平台差异与可选特性，不要隐藏业务逻辑。 |
| `#undef` | 取消宏定义 | 限制宏污染范围。 |

避免宏参数被多次求值：`#define SQUARE(x) ((x) * (x))` 遇到 `SQUARE(i++)` 会产生副作用。能用 `const`、`enum`、`static inline` 时，通常优先不用函数式宏。
